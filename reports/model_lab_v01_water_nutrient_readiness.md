# Western Basin Model Lab v0.1 — water and nutrient readiness

**Audit basis:** clean `main` and `origin/main` at `e710583fbc1d6d2f8191244d2e1b98770f2d7907`. This is a design recommendation, not a new scientific baseline, calibrated model, forecast, or Atlas publication decision. No outside data were added.

## Decision

Start with a **period-based HUC-12 routing and mass-accounting ledger** for explicitly supplied water, total nitrogen (TN), and total phosphorus (TP). Its first run should use clearly synthetic unit inputs to verify topology and conservation. A later run may accept documented, period-matched inputs; the current repository does **not** contain enough such inputs to calculate observed basin loads or close an empirical water/N/P budget. This is still the best starting domain: the project has a qualified downstream HUC network and strong nutrient claim boundaries, while its other water and material-flow graphs are primarily conceptual.

The model's useful first result is inspectable **conditional delivery and unresolved-routing exposure**, not a numerical estimate of Maumee or Lake Erie loading.

## Network choice and scientific limit

Use HUC-12 as an **accounting unit**, not a claim of homogeneous catchment behavior. Read the 252 HUC IDs and the 251 qualified current links as a directed graph. A read-only topology check found one successor per linked HUC, no cycles, 119 graph headwaters, and one terminal project HUC, `041000090904` (Delaware Creek–Maumee River). WBD points onward to out-of-extract `041202000300`; create an explicit **model-boundary export** there. It is not a measured Maumee mouth or lake load. Twelve links remain low-confidence project inferences, including ambiguous outlets and divergence/direction issues.

The finer 3DHP network is inappropriate for the first quantitative engine: it has native direction evidence but many divergences, missing downstream references, and no branch discharge fractions. Agricultural tile drainage is incomplete. A default run should **stop forwarding quantity at each unresolved link** and report it as unrouted; a clearly named sensitivity run may pass it along the WBD successor. Do not silently treat that sensitivity as authoritative or turn the 12 lines into waterways. Do not use the qualitative Phase 8A edge table as numeric topology.

## Smallest executable model worth building

**Purpose.** Trace supplied period totals through the accepted HUC graph and prove a node-by-node accounting identity. No 2075 or HAB prediction, concentration calculation, travel time, residence time, storage dynamics, or inferred wetland/soil performance.

**Inputs.** One row per `run_id × period × huc12 × constituent` for local volume (`water`, m³/period) or mass (`TN`/`TP`, kg/period); every row carries `input_status` (`synthetic_diagnostic`, `parameterized`, or `observed_derived`), source ID, method, and uncertainty note. Diagnostic unit-pulse files may be sparse with omitted HUC inputs explicitly defined as zero; a future empirical input set must declare and verify coverage instead of treating missing observations as zero. Do not mix constituent forms or periods. A separate per-run assumption record controls unresolved-link policy and, only when explicitly supplied, a HUC/constituent pass-through fraction. Default pass-through is **1**, so no unobserved retention is implied. Negative inputs, unknown HUC IDs, incompatible units, or unknown status must fail validation.

**Per-HUC ledger.** The reference case assumes transfer within one accounting period, with no represented lag, storage, water loss, or nutrient transformation. For constituent *x*, `available = local_input + sum(upstream_out)`, `not_forwarded_assumed = available × (1 − pass_through)`, and `remainder = available − not_forwarded_assumed`. Send the remainder to the qualified downstream HUC; record it as `unrouted_at_unresolved` at a cut link; or record it as `boundary_export` at the terminal HUC. Both nonforwarded categories are **accounting dispositions**, not measured storage, treatment, ecological retention, or evidence of nutrient removal. With every quantity in one declared period, require `local_input + upstream_in − not_forwarded_assumed − unrouted_at_unresolved − downstream_out − boundary_export = 0` at every HUC and constituent. At run level, **for each constituent separately**, summed local inputs must equal summed amounts not forwarded by assumption, unrouted at unresolved links, and exported at the boundary. Zero-pass-through or fractional sensitivity values require explicit parameter provenance and a prominent hypothetical label.

**Outputs.** Stable, machine-readable `run_manifest.json` (source hashes, code version, period, units, input/assumption status), `huc_balance.csv` (the ledger terms, residual, routing QA and source flags), `edge_flux.csv` (qualified HUC-to-HUC transfers), and `boundary_summary.csv` (totals, unresolved amount, export, closure). Keep numbers at source precision; do not manufacture decimals. Separate diagnostic unit-pulse runs from any future empirical run by status and file name. These tables can drive both static figures and a later interface without rerunning science in a browser.

**Validation.** Check HUC uniqueness/coverage, graph acyclicity, topological order, exactly one terminal, admissible routing classes, explicit treatment of all 12 unresolved links, units/periods/forms, nonnegative values, node and global closure, zero-input behavior, and a one-HUC unit-pulse trace. Compare strict versus pass-through routing sensitivity; do not label the latter calibrated. An independent small R balance check is useful once the Python run format stabilizes. A numeric closure residual proves implementation arithmetic only, not an observed basin balance.

## Graphics, code placement, and later interface

First graphics should be diagnostic: (1) HUC network/map colored by topology and unresolved-link status; (2) a simple bar/waterfall of supplied input, quantity not forwarded by assumption, quantity unrouted at unresolved links, and boundary export; (3) a node residual plot. A routed-load map is appropriate only when its input status is unmistakable. Defer a proportional Sankey or baseline-versus-alternative load graphic until an explicit, compatible input set exists; never plot targets as observed sources.

Python should prepare inputs, traverse the graph, write the ledger, and render first static QA figures, matching existing `src/python/systems/` builders and `src/python/qa/` topology work. R already serves independent validation/rendering; later Shiny can **read the versioned output tables and provenance**, starting with a HUC selection/upstream trace and a mass-balance/assumption view. Keep the engine outside Shiny. Do not build dashboard screens before stable run outputs exist.

For the next transaction, add only `src/python/model_lab/route_water_nutrients.py` plus a small validator, `data/model_lab/` for explicitly labeled run inputs/configuration, and `outputs/model_lab/<run_id>/` for run tables/diagnostics. Add `src/R/model_lab/` when an independent check or Shiny actually needs it. Read the frozen `data/processed/` and source files; write no new modeling results into protected Phase 1–16 products. A separate Shiny area can be chosen later rather than scaffolding it now.

## What is missing, and build order

1. **Build the structural prototype:** copy only HUC IDs/routing status into run-local inputs, verify the graph and boundary, then run unit pulses with default pass-through of one. Produce the ledger and three diagnostic graphics. Gate outputs on the validations above.
2. **Add controlled sensitivity:** allow a documented pass-through assumption and explicit policy for the 12 unresolved links. Report how much synthetic/supplied material is not forwarded or depends on those links. This is a scenario-control experiment, not a claim of realized nutrient retention.
3. **Prepare real-data readiness separately:** identify and license period-matched TN/TP observations or loads; verify a Waterville gauge crosswalk and compatible discharge record; seek defensible distributed runoff/source-load estimates, point-source actual discharges, diversions, and uncertainty. Record coverage and gaps before attempting calibration. Repository references to NCWQR, EPA, and monitoring programs are leads, not ingested calibration series.
4. **Only then assess empirical calibration:** compare like periods, chemical forms, and spatial boundaries; hold out independent observations where available. Without them, retain the structural/conditional label. A Shiny read-only view follows a stable, useful output schema.

**Protected boundary:** Phase 1–16 freeze manifests and their artifacts remain read-only. The historical intake-crib observation coordinate and held Great Black Swamp candidate geometry are irrelevant to this HUC accounting prototype and must not be silently repurposed. No canon, futurescape, public Atlas, or Phase 17D change follows from this report.
